# Phase 70 provider-connection migration (v2.x)

Phase 70 is released as a backward-compatible v2.x update. The new PostgreSQL
package and provider-connection APIs are additive; existing core PostgreSQL
adapters and `fred-http` stores continue to work and emit a deprecation warning.
The expected release set from `bun changeset status` is:

| Package | Release |
| --- | --- |
| `@fancyrobot/fred` | `2.x` minor |
| `@fancyrobot/fred-postgres` | `1.x` minor |
| `@fancyrobot/fred-cli` | `0.x` minor |
| `@fancyrobot/fred-http` | `1.x` minor |
| Provider packages | additive minor/patch |

Release automation owns exact manifests, changelogs, internal dependency
ranges, and lockfile changes. Confirm this cohort with `bun changeset status`
and rehearse `bun run ci:version` in a disposable checkout; never edit package
versions or changelogs by hand and never run `bun run ci:publish` locally.

## Required code changes

```ts
// Existing v2 code continues to work (with a deprecation warning).
import { PostgresContextStorage } from '@fancyrobot/fred';

// New code should install and import the canonical adapter package.
import { PostgresContextStorage } from '@fancyrobot/fred-postgres';
```

For the new adapter package, migrate into a dedicated Fred schema before
constructing runtime adapters. Existing core adapters retain their v2 runtime
DDL behavior. If older Fred tables exist in `public`, take a backup and use the
explicit copy-only importer after a rehearsal. The migration never auto-adopts,
renames, or deletes application-owned objects.

Saved provider connections must use explicit UUID `connectionId` selection and
a non-empty consumer-owned `connectionNamespace`. List, get, put, remove, and
saved resolution calls all require the namespace; no default namespace exists.
Leaving it out remains a compatibility path for the documented environment
variables only; it is not a default-saved-connection lookup.

Rollback is package-compatible only. Database migrations are forward-only:
roll forward or restore a verified backup rather than attempting a down
migration or destructive cleanup.
