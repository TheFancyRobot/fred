# Phase 70 provider-connection migration

The Phase 70 Changesets release advances the affected public packages by a
major version because PostgreSQL adapters moved out of core and consumers must
choose the new explicit connection-storage boundary. The expected release set
from `bun changeset status` is:

| Package | Release |
| --- | --- |
| `@fancyrobot/fred` | `3.0.0` |
| `@fancyrobot/fred-postgres` | `2.0.0` |
| `@fancyrobot/fred-cli` | `1.0.0` |
| `@fancyrobot/fred-http` | `2.0.0` |
| `@fancyrobot/fred-openai`, `-anthropic`, `-google`, `-groq` | `5.0.0` |
| `@fancyrobot/fred-openrouter` | `6.0.0` |
| `@fancyrobot/fred-minimax` | `3.0.0` |

Release automation owns exact manifests, changelogs, internal dependency
ranges, and lockfile changes. Confirm this cohort with `bun changeset status`
and rehearse `bun run ci:version` in a disposable checkout; never edit package
versions or changelogs by hand and never run `bun run ci:publish` locally.

## Required code changes

```ts
// Before: Postgres adapter imported from core.
import { PostgresContextStorage } from '@fancyrobot/fred';

// After: install and import the canonical adapter package.
import { PostgresContextStorage } from '@fancyrobot/fred-postgres';
```

Migrate into a dedicated Fred schema before constructing runtime adapters. If
older Fred tables exist in `public`, take a backup and use the explicit
copy-only importer after a rehearsal. The migration never auto-adopts,
renames, or deletes application-owned objects.

Saved provider connections must use explicit UUID `connectionId` selection.
Leaving it out remains a compatibility path for the documented environment
variables only; it is not a default-saved-connection lookup.

Rollback is package-compatible only. Database migrations are forward-only:
roll forward or restore a verified backup rather than attempting a down
migration or destructive cleanup.
