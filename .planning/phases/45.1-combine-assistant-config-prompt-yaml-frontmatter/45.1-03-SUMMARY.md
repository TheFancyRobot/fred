## Decisions Made
- Hot reload callback always attempts `removeAgent(previousId)` before creating a replacement config to preserve in-place replacement semantics
- Reload parse/validation failures are warned and non-fatal, with known agents emitted as removal events so stale invalid definitions are not left active
- Watcher instance ownership is centralized in `Fred` and replaced/closed via `setAgentFileWatcher` to avoid multiple active watcher leaks
