**B. Add updateTelemetryModel method to app.ts**

In `packages/cli/src/tui/app.ts`, add a public method to `FredTuiApp` class:

```typescript
updateTelemetryModel(model: string, provider: string): void {
  this.state = {
    ...this.state,
    telemetry: {
      ...this.state.telemetry,
      model,
      provider,
    },
  };
  this.events.onStateChange?.(this.state);
  this.syncStateToUI();
}
```

Place it near the other public streaming API methods (after `failAssistantStream`). This allows the chat command to update telemetry once the provider/model is known.

Return default models appropriate for each provider (e.g., openai -> 'gpt-4o-mini', anthropic -> 'claude-3-5-haiku-latest', google -> 'gemini-2.0-flash', groq -> 'llama-3.1-8b-instant', openrouter -> 'openai/gpt-4o-mini').

3. Add an `async initializeFred()` function that:
   - Creates `new Fred()`
   - Tries `resolveProjectConfig()` -- if success, calls `fred.initializeFromConfig(configPath)` and extracts model info from config (first agent's platform/model)
   - If no config found, calls `fred.registerDefaultProviders()`, then uses `detectAvailableProvider()` to find a provider
   - If a provider is found and no agents exist, calls `fred.useProvider(platform)` then `fred.createAgent({ id: '__tui_agent__', systemMessage: 'You are a helpful assistant.', platform, model, tools: ['calculator'] })`
   - Returns `{ fred, model, provider }` or throws if no provider available
   - Wrap provider/agent creation in try/catch with clear error messages

4. Modify `handleChatCommand()` in the interactive-tty branch:
   - After creating the TUI app via `createFredTuiApp(...)`, call `initializeFred()`
   - Pass an `onSubmit` callback to `createFredTuiApp` that does NOT call `app.startAssistantStream()` (because `submitCurrentInput()` in app.ts already calls `startStreaming()` and `streamingController.start()` at lines 377-380 -- calling it again would be redundant/conflicting). Instead, the onSubmit callback should:
     a. Iterate `fred.streamMessage(text).fullStream` with `for await`
     b. For each event with `type === 'token'` and a non-empty `delta`, call `app.pushAssistantToken(event.delta, 1)`
     c. For `type === 'usage'` events, update token counts if available (this is optional -- the app already estimates tokens)
     d. After the loop completes, call `app.completeAssistantStream()`
     e. Wrap everything in try/catch -- on error, call `app.failAssistantStream(error)`
   - After `initializeFred()` succeeds, call `app.updateTelemetryModel(model, provider)` to set the real model name in the status bar
   - If `initializeFred()` fails, show the error in the transcript via a system message (e.g., append an assistant message like "Error: No AI provider configured. Set OPENAI_API_KEY or another provider API key." and stop streaming)

Important implementation details:
- The `onSubmit` callback must NOT call `app.startAssistantStream()` because `submitCurrentInput()` in app.ts already calls `startStreaming()` and `streamingController.start()` (lines 377-380). The onSubmit callback should ONLY handle the Fred API call and token feeding.
- The streaming loop must be async (use `for await`) and should not block the TUI event loop. The `onSubmit` callback should fire the async stream processing without awaiting it (fire-and-forget with error handling).
- Use `event.delta` for token text (not `event.accumulated` which is the full text so far).
- The `@fancyrobot/fred` package is already a dependency of `@fancyrobot/fred-cli` (see package.json dependencies).
