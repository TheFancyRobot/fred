  <action>
In intent.ts, wrap each of the 5 error paths so that when `options.json === true`, the command outputs `{ "ok": false, "error": "..." }` via `io.stdout` instead of writing plain text to `io.stderr`. The `options` parameter is already available in both `handleIntentTest` and `handleIntentCommand`.

Specific error paths in intent.ts:
1. Line 60 (missing message): Check `options.json`; if true, `io.stdout(JSON.stringify({ ok: false, error: 'Message required. Usage: fred intent test "message"' }, null, 2))` instead of `io.stderr(...)`. Still return exit code 2.
2. Line 69 (Fred init failure): Same pattern — JSON to stdout or plain text to stderr.
3. Line 75 (no intents registered): Same pattern.
4. Line 85 (intent matching failed): Same pattern.
5. Line 184 (unknown subcommand in `handleIntentCommand`): Same pattern.

Apply the IDENTICAL pattern to route.ts for its 5 error paths:
1. Line 59 (missing message)
2. Line 68 (Fred init failure)
3. Line 78 (routing failed)
4. Line 85 (routing not configured)
5. Line 195 (unknown subcommand in `handleRouteCommand`)

The pattern for each error path is:
```typescript
if (options.json === true) {
  io.stdout(JSON.stringify({ ok: false, error: 'The error message without exit code prefix' }, null, 2));
} else {
  io.stderr('Error (exit 2): The error message');
}
return 2;
```

Do NOT include the "Error (exit N):" prefix in the JSON error string — that is for human-readable output only. The JSON error field should contain just the descriptive message.

Do NOT change any success paths or non-error behavior.

3. `handleMcpStart` — single server start failure (lines 196-203): Same exclusive pattern. Remove the extra stderr hint line ("Try running with --verbose...") from the JSON branch.
4. `handleMcpStop` — missing server ID (lines 241-246): Same exclusive pattern.

6. `handleMcpStatus` — missing server ID (lines 280-286): Same exclusive pattern.
7. `handleMcpStatus` — server not found (lines 291-297): Same exclusive pattern.

9. `handleMcpCommand` — catch-all error (lines 392-394): Add JSON handling. When `options.json`, output `{ ok: false, error: message }` to stdout.
