THREE independent fixes in app.ts:

**Fix 1: Paste event handler**

The `registerKeyboardHandler()` method (line 468-473) only listens for `'keypress'` events. OpenTUI's `KeyHandler` also emits `'paste'` events (with `PasteEvent` containing a `.text` property) when bracketed paste is detected.

Add a paste listener in `registerKeyboardHandler()`:

```typescript
this.renderer.keyInput.on('paste', (event: PasteEvent) => {
  if (!this.running) return;
  if (this.state.focusedPane !== 'input') return;
  if (this.state.commandPalette.isOpen) return;

  // Insert pasted text at cursor position
  const text = event.text.replace(/\n/g, ' '); // Flatten newlines for single-line input
  const before = this.state.input.text.slice(0, this.state.input.cursorPosition);
  const after = this.state.input.text.slice(this.state.input.cursorPosition);
  this.state = {
    ...this.state,
    input: {
      ...this.state.input,
      text: before + text + after,
      cursorPosition: this.state.input.cursorPosition + text.length,
    },
  };
  this.events.onStateChange?.(this.state);
  this.syncStateToUI();
});
```

Import `PasteEvent` from `@opentui/core` (add to the existing import block at line 8-18). Check the `@opentui/core` type exports — `PasteEvent` is exported from `lib/KeyHandler`. It may be re-exported from the main index. If not directly available, import from `@opentui/core/lib/KeyHandler` or use the type inline.

**Fix 2: Auto-scroll to bottom on message send**

In `submitCurrentInput()` (line 730), after `this.state = appendUserMessage(this.state, submittedText)` (line 739), add a call to reset the OpenTUI ScrollBoxRenderable's scroll position:

```typescript
// Reset OpenTUI scroll position to bottom on new message send
// This overrides _hasManualScroll so stickyScroll re-engages
this.transcriptContent.scrollTo(Infinity);
```

`scrollTo(Infinity)` on a ScrollBoxRenderable with `stickyStart: 'bottom'` will scroll to the maximum scroll position (bottom), which also resets `_hasManualScroll` to false (the renderable detects it's at the sticky position). Place this call right after `appendUserMessage` and before the first `syncStateToUI()` that follows it, or at the end of the non-early-return path (around line 773, just before the final `syncStateToUI()`).

**Fix 3: Scroll acceleration**

In `buildComponentTree()`, where `this.transcriptContent` is created (lines 407-415), add `scrollAcceleration` to the ScrollBoxRenderable options:

```typescript
import { MacOSScrollAccel } from '@opentui/core';
// or: import { MacOSScrollAccel } from '@opentui/core/lib/scroll-acceleration';
```

Add to the ScrollBoxRenderable constructor options:
```typescript
scrollAcceleration: new MacOSScrollAccel(),
```

Then in `handleTranscriptMouseScroll()` (lines 1494-1513), instead of using the custom state-based scroll path, delegate to the OpenTUI ScrollBoxRenderable's native scroll handling. Replace the method body:

```typescript
private handleTranscriptMouseScroll(event: MouseEvent): void {
  const direction = event.scroll?.direction;
  if (!direction) return;

  const delta = event.scroll?.delta ?? 1;
  // Let OpenTUI's ScrollBoxRenderable handle scroll with acceleration
  const scrollAmount = direction === 'up' ? -delta : delta;
  this.transcriptContent.scrollBy(scrollAmount);

  // Also update TUI state for scroll position tracking
  const lines = Math.max(1, Math.round(Math.abs(scrollAmount)));
  if (direction === 'up') {
    this.state = scrollTranscript(this.state, -lines);
  } else {
    this.state = scrollTranscript(this.state, lines);
  }
  this.events.onStateChange?.(this.state);
  this.syncStateToUI();
}
```

Note: Check if `MacOSScrollAccel` is exported from `@opentui/core` main entry or needs a deep import path. The d.ts file is at `lib/scroll-acceleration.d.ts`. Try `import { MacOSScrollAccel } from '@opentui/core'` first; if TypeScript can't find it, use `import { MacOSScrollAccel } from '@opentui/core/lib/scroll-acceleration'`.

UAT Test 1 reported: "apparently i also can't copy text from the transcription window." The root cause is that `useMouse: true` at app.ts:196 captures all mouse events at the terminal level, preventing native text selection. The existing `copyTranscriptToClipboard` (lines 1097-1104) copies the ENTIRE transcript, not individual messages. Users need a way to copy a specific message.

**Implementation: Copy focused/last-assistant message via keybinding**

Add a keybinding (Ctrl+Y or another available key) that copies the content of the most recent assistant message (or the currently-focused message if message focus tracking exists) to the system clipboard.

1. **Find the message to copy:** Look at `this.state.transcript.messages` array. Get the last assistant message:
```typescript
const lastAssistantMsg = [...this.state.transcript.messages]
  .reverse()
  .find(m => m.role === 'assistant');
```

2. **Extract text content:** The message's `content` field contains the text. For assistant messages, extract the text content (may need to handle different content types — check the message type definition). Typically `message.content` is a string or has parts.

3. **Copy to clipboard:** Use the same clipboard mechanism as `copyTranscriptToClipboard`. Check what it uses — likely `clipboardy` or a Bun subprocess calling `xclip`/`xsel`/`pbcopy`. Reuse that same approach.

4. **Register the keybinding:** In `handleKeypress()` or the keyboard handler, add a case for the copy key (e.g., Ctrl+Y):
```typescript
// Ctrl+Y: Copy last assistant message
if (key.ctrl && key.name === 'y') {
  this.copyLastAssistantMessage();
  return;
}
```

5. **Show feedback:** After copying, briefly show a status message (e.g., update the status bar text to "Copied to clipboard" for 2 seconds). If a toast/notification mechanism exists, use it. Otherwise, a simple approach: set a state flag that the status bar reads, clear it after a timeout.

6. **Add to help/shortcuts display:** If there is a keyboard shortcuts display (status bar badges or help screen), add the copy shortcut.

**Note:** This approach does not require disabling `useMouse: true` (which is needed for scroll handling). Instead, it provides a keyboard-driven copy mechanism. Native text selection remains unavailable with mouse capture enabled — this is an inherent trade-off of TUI mouse support. The per-message copy provides a practical alternative.
