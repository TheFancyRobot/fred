<objective>
Migrate transcript rendering from string-based lines to per-message renderable trees with distinct user/assistant styling, markdown rendering for assistant content, and streaming accent color.

Purpose: Replaces the flat `renderTranscriptContent` returning `lines[]` with renderable builders that produce `BoxRenderable` containers per message. User messages get left-border accent on base background. Assistant messages get surface background with `MarkdownRenderable` for rich text. Streaming content uses warm amber accent with instant transition to normal on completion.

Output: Renderable-based transcript with visual distinction between user/assistant messages, markdown rendering, streaming accent, and auto-scroll.
</objective>

**theme.ts changes:**

Extend `TuiTheme` interface with a `message` group containing semantic tokens for transcript rendering:

```typescript
message: {
  userBorder: string;     // User message left border color
  userBg: string;         // User message background (alias for bg.base)
  assistantBg: string;    // Assistant message background (alias for bg.surface)
  codeBg: string;         // Code block background (one step above surface)
  thinkingFg: string;     // Thinking block text (heavily dimmed)
  streamingFg: string;    // Streaming accent foreground (warm amber)
  toolConnector: string;  // Tool block tree connector color (gray)
  taskAccent: string;     // Task/subagent block accent (blue)
  errorAccent: string;    // Failed tool/task accent (red)
};
```

Add values to `DEFAULT_TUI_THEME.message`:
- `userBorder`: use `accent.primary` value (`#5ec2c7` teal) — per research recommendation
- `userBg`: use `bg.base` value (`#121417`)
- `assistantBg`: use `bg.surface` value (`#181c21`)
- `codeBg`: use `bg.elevated` value (`#1f252b`) — one step above surface
- `thinkingFg`: a very dim color, e.g. `#5a5f66` (between dim and base)
- `streamingFg`: use `accent.streaming` value (`#d4a259` warm amber)
- `toolConnector`: use `fg.dim` value (`#8b9199`)
- `taskAccent`: use `status.info` value (`#6fa6d9`)
- `errorAccent`: use `status.error` value (`#d97b7b`)

**layout.ts changes:**

Add new exported functions that build renderable trees for individual messages. These functions accept a `CliRenderer`, `TuiTheme`, message data, and return renderable nodes. Import `BoxRenderable`, `TextRenderable`, `MarkdownRenderable`, `SyntaxStyle`, `TextAttributes` from `@opentui/core`.

1. `buildUserMessageRenderable(renderer, theme, content, id)` -> `BoxRenderable`:
   - Container: `BoxRenderable` with `flexDirection: 'column'`, `backgroundColor: theme.message.userBg`, `border: ['left']`, `borderStyle: 'single'`, `borderColor: theme.message.userBorder`, `paddingLeft: 2`, `paddingRight: 2`, `paddingTop: 0`, `paddingBottom: 0`, `marginBottom: 1`
   - Child: `TextRenderable` with content, `fg: theme.fg.primary`, `selectable: true`
   - ID: `msg-user-${id}`

2. `buildAssistantMessageRenderable(renderer, theme, content, id, options: { streaming: boolean, syntaxStyle: SyntaxStyle })` -> `BoxRenderable`:
   - Container: `BoxRenderable` with `flexDirection: 'column'`, `backgroundColor: theme.message.assistantBg`, `paddingLeft: 2`, `paddingRight: 2`, `paddingTop: 0`, `paddingBottom: 0`, `marginBottom: 1`, NO border
   - Child: `MarkdownRenderable` with content, `syntaxStyle: options.syntaxStyle`, `streaming: options.streaming`, `conceal: false`
   - When streaming, set `fg` on the MarkdownRenderable (or parent box) to `theme.message.streamingFg` for warm amber accent
   - ID: `msg-assistant-${id}`, markdown child ID: `msg-assistant-md-${id}`

3. `buildThinkingRenderable(renderer, theme, content, id)` -> `BoxRenderable`:
   - Container: `BoxRenderable` with `flexDirection: 'column'`, `backgroundColor: theme.message.assistantBg`, `paddingLeft: 2`, `paddingRight: 2`, `marginBottom: 1`
   - Child: `TextRenderable` with content, `fg: theme.message.thinkingFg`, `attributes: TextAttributes.DIM | TextAttributes.ITALIC`
   - ID: `msg-thinking-${id}`

4. `buildStreamingCursorText()` -> returns the block cursor character `\u2588` that gets appended to streaming content. This is NOT a separate renderable -- it's appended to the markdown content string during streaming and removed on completion.

Keep `renderTranscriptContent` functional for the startup chooser and empty state -- these special cases still return `PaneContent` with `lines[]`. Add a new export `getTranscriptMessages(state: TuiState)` that returns the messages array for the current session, so app.ts can build renderables from it.

Do NOT delete `renderTranscriptContent` -- it is still used for startup chooser overlay and empty state. But the normal message rendering path will bypass it.

**app.ts changes:**

Import `MarkdownRenderable`, `SyntaxStyle` from `@opentui/core`. Import the new builder functions from layout.ts.

Add a class-level `SyntaxStyle` instance created once in the constructor (NOT per render cycle -- this allocates native FFI resources). Store as `private syntaxStyle: SyntaxStyle`. Call `this.syntaxStyle = SyntaxStyle.create()` in the constructor. Add cleanup in `stop()`: `this.syntaxStyle?.destroy()`.

Add a `private activeStreamingMdId: string | null = null` field to track the currently streaming MarkdownRenderable ID for incremental updates.

**Modify `buildComponentTree()`:**
Change the `transcriptContent` ScrollBoxRenderable to use `stickyScroll: true` and `stickyStart: 'bottom'` for auto-scroll behavior. This replaces the manual viewport scroll offset math for auto-scroll-to-bottom.

**Modify `syncStateToUI()` transcript section:**
Replace the current string-line-based transcript rendering block. The new approach:

1. For startup chooser and empty state, keep the existing `renderTranscriptContent` path (string lines rendered as TextRenderable children, same as before).

2. For normal messages, use the new renderable builders:
   - Get messages from state (use `getTranscriptMessages` or directly from `state.transcript.messages`)
   - If the `activeStreamingMdId` is set and the last message is an assistant message that is being streamed to (i.e., `state.streaming.isStreaming`), find the existing MarkdownRenderable by ID and update its `content` property in place (incremental update, no tree rebuild). Append the block cursor character during streaming.
   - Otherwise (not streaming, or messages changed), rebuild the transcript renderable tree:
     - Clear all children from `transcriptContent` ScrollBox
     - For each message, call the appropriate builder function
     - For assistant messages: `streaming` option is `true` only for the LAST message when `state.streaming.isStreaming` is true
     - Track the `activeStreamingMdId` so subsequent streaming batches can update in place

3. When streaming transitions to complete (`finishStreaming` called): Find the active MarkdownRenderable, set `streaming = false`, remove the block cursor from content, switch fg color from `streamingFg` to normal (remove streaming accent). Reset `activeStreamingMdId = null`. Since the streaming accent needs to switch instantly, this is done by updating the parent BoxRenderable's fg or the MarkdownRenderable's properties.

4. Detect `<thinking>` blocks in assistant messages: If content contains `<thinking>...</thinking>` tags, split content into thinking and non-thinking segments. Render thinking segments with `buildThinkingRenderable` and non-thinking segments with `buildAssistantMessageRenderable`. For simplicity in v1, detect thinking tags and render the entire message as thinking if it starts with `<thinking>`, or render normally. Refine if needed.

**Key anti-patterns to avoid:**
- Do NOT rebuild the entire renderable tree on every streaming batch -- only update the active MarkdownRenderable's content
- Do NOT create a new SyntaxStyle per render -- use the single instance
- Remove the old `repopulateScrollBox` call for transcript content (keep it for sidebar)
- The manual viewport offset math (`transcriptData.scrollOffset`, `transcriptData.totalLines`, etc.) can be simplified since stickyScroll handles auto-scroll. Keep the manual scroll for user-initiated scrolling but let stickyScroll handle the streaming-follows-bottom behavior.

**state.ts changes (minimal):**
No major state model changes needed for this task. The message model (`{ role: string; content: string }`) stays the same. The viewport math in `countMessageLines` becomes less critical since stickyScroll handles most of the auto-scroll, but keep it for now to avoid breaking scroll keyboard shortcuts. Can be cleaned up later.

**Streaming batch handling:**
In `handleStreamingBatch`, after calling `appendAssistant`, the `syncStateToUI` will detect that streaming is active and the last message is assistant, and will do an incremental update of the existing MarkdownRenderable instead of rebuilding.

**Error state during streaming:**
When `recordStreamingError` is called, the streaming accent should immediately switch to error accent. Handle this in the `syncStateToUI` rendering path.
