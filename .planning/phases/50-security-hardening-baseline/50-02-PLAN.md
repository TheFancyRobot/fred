  <name>Task 1: Add allowlist types, security module, and tests</name>
  <files>packages/core/src/mcp/types.ts, packages/core/src/mcp/security.ts, tests/unit/mcp/security.test.ts</files>
  <behavior>
    - validateCommand: command in allowlist -> no error
    - validateCommand: command not in allowlist -> throws MCPSecurityError with command name and allowlist
    - validateCommand: allowedCommands undefined -> no validation (pass through)
    - validateCommand: allowedCommands empty array -> all commands rejected
    - validateUrl: host in allowedHosts -> no error
    - validateUrl: host not in allowedHosts -> throws MCPSecurityError
    - validateUrl: scheme in allowedSchemes -> no error
    - validateUrl: scheme not in allowedSchemes (e.g. http when only https allowed) -> throws MCPSecurityError
    - validateUrl: allowedHosts/allowedSchemes undefined -> no validation (pass through)
    - validateUrl: invalid URL string -> throws MCPSecurityError
    - filterEnv: with allowlist ['PATH', 'HOME'] -> only PATH and HOME from process.env, plus explicit env overrides
    - filterEnv: with undefined allowlist -> uses default allowlist (PATH, HOME, USER, SHELL, NODE_ENV, LANG, TERM)
    - filterEnv: explicit per-server env always merges on top of filtered base
  </behavior>
  <action>
    1. Extend `MCPServerConfig` in `packages/core/src/mcp/types.ts` with four optional fields:
       - `allowedCommands?: string[]` — permitted executables for stdio transport
       - `allowedHosts?: string[]` — permitted hostnames for http/sse transport
       - `allowedSchemes?: string[]` — permitted URL schemes for http/sse (default: ['https'] when allowedHosts is set)
       - `envAllowlist?: string[]` — env vars to pass to stdio child processes

    2. Create `packages/core/src/mcp/security.ts`:
       - Export `MCPSecurityError` class extending Error with `readonly code: string` field ('COMMAND_DENIED' | 'URL_DENIED' | 'SCHEME_DENIED').
       - Export `validateCommand(command: string, allowedCommands?: string[]): void` — throws MCPSecurityError if allowedCommands is defined and command is not in list.
       - Export `validateUrl(url: string, allowedHosts?: string[], allowedSchemes?: string[]): void` — parses URL, checks host against allowedHosts (if defined), checks scheme against allowedSchemes (if defined). Throws MCPSecurityError on violation.
       - Export `DEFAULT_ENV_ALLOWLIST = ['PATH', 'HOME', 'USER', 'SHELL', 'NODE_ENV', 'LANG', 'TERM']`.
       - Export `filterEnv(envAllowlist?: string[], explicitEnv?: Record<string, string>): Record<string, string>` — builds filtered base from process.env using allowlist (or DEFAULT_ENV_ALLOWLIST), then merges explicitEnv on top.

    3. Create `tests/unit/mcp/security.test.ts` covering all behaviors above. Tests should NOT spawn real processes — test the validation and filtering functions directly.
  </action>
  <verify>
    <automated>bun test tests/unit/mcp/security.test.ts</automated>
  </verify>
